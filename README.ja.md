# premiere-autoedit

**[English](README.md) · 日本語**

**文章や参考動画から、Premiere Pro のラフカットを自動で組み立てるツールです。**

どんな動画かを一文で書きます。渡された素材をすべて読み、使えるショットを見つけ、話し声または音楽のビートに合わせて切り、Premiere に実際のシーケンスを作ります。すべてのクリップにそれを選んだ理由が付いているので、どの判断にも異議を唱えられます。

```
「キッチンの15秒プロモ、テンポ速め」
        │
        ├─ 40分のラッシュを読む（ショット、顔、動き、シャープさ）
        ├─ 使えないものを捨てる（黒コマ、フリーズ、ピント不良、手ブレ）
        ├─ 残りを選んで並べる（書いた言葉どおり、または音楽のビートに）
        └─ Premiere にシーケンスを作る（新規、開いているものは上書きしない）
```

編集判断そのものを置き換えようとはしていません。半日かかるのに何も考えることのない機械的な部分だけを引き受け、そのうえですべての判断を説明するので、あなたがそれを覆せます。タイムライン上のクリップにはそれぞれ、なぜ選ばれたかと、ツールがどの程度確信していたかが付いています。どのショットにも差し替え候補があり、クリックひとつで入れ替えられます。

**やらないこと：** カラーグレーディング、音声のミックス、台本の執筆、そして開いているシーケンスへの変更。必ず新しいシーケンスを作ります。

**仕上げはあなたの仕事です。** 8割正しいラフ編集は半日の価値がありますが、そのまま公開できるものではありません。

> **この日本語ドキュメントは作者が書いたもので、母語話者によるものではありません。** 訂正は [Issue](https://github.com/OwenLangley/premiere-autoedit/issues) でも Pull Request でも歓迎します。このプロジェクトが最も必要としている貢献です。

## 必要なもの

| | |
|---|---|
| **macOS** | Apple Silicon・Intel のいずれも。Windows では一度も動作させていません。 |
| **Premiere Pro 26.3 以降** | 26.0 と 26.2 にはパネルが呼び出す API がありません。「Premiere Pro について」で確認できます。 |
| **空き容量 約4 GB** | 音声認識とショット認識のモデル用。初回のみダウンロードします。 |
| **Homebrew** | ffmpeg と Python のために使います。[brew.sh](https://brew.sh) |

**素材がマシンの外に出ることはありません。** 文字起こしもショット認識もすべてローカルで動きます。ネットワークに触れるのは、初回のモデルのダウンロードと、参考動画のリンクを貼った場合のその動画の取得だけです。

## インストール

```bash
brew install ffmpeg python@3.11
git clone https://github.com/OwenLangley/premiere-autoedit.git
cd premiere-autoedit
./setup.sh ~/Footage
```

`~/Footage` は個々の撮影ではなく、ラッシュ全体の一番上のフォルダです。ここだけは自分で決める必要がありますが、あとからパネル内で変更でき、何かを再実行する必要はありません。セットアップは Python エンジン、Premiere パネル、バックグラウンドヘルパーの3つをインストールします。途中で一度パスワードを訊かれますが、これは Premiere 26 が `/Library` からしかプラグインを読み込まないためです。

そのあと **Premiere を終了して開き直し**、**ウィンドウ → UXP プラグイン → AutoEdit** を開きます。

`./setup.sh --check` は、何も変更せずに、そのマシンに足りないものだけを報告します。

> **バックグラウンドヘルパーは省略できません。** Premiere のパネルはプロセスを起動できないため、パネルが要求を書き出し、ヘルパーがエンジンを実行します。これが動いていないと、パネルは完全に正常に見えるのに **「編集を作成」を押しても何も起こりません**。エラーもどこにも出ません。`--check` はこれを重点的に確認します。

## 最初に一度だけ設定する

パネルの **設定** で：

1. **ジョブフォルダ** — セットアップが表示したフォルダ（`~/Desktop/AutoEdit-jobs`）を選びます。このクリックだけはスクリプト化できません。プラグインがフォルダにアクセスできるのは、自分で操作したピッカーを通した場合だけだからです。
2. **素材フォルダ** — ラッシュの場所です。`setup.sh` に渡していればすでに設定されています。
3. **音楽フォルダ**（任意） — 音楽ライブラリの場所。素材がどこにあるかとは関係ありません。
4. **参考動画フォルダ**（任意） — 「このように切ってほしい」と思う動画の置き場所。

設定は完了すると一行に畳まれ、パネルの場所を取らなくなります。**設定 → パネルの言語** で日本語と英語を切り替えられます。

## 編集を作る

1. **内容を書く。** 日本語でも英語でも、一文で。*「キッチンの15秒プロモ、テンポ速め」*。**名前（任意）** を空欄にすると、日付と時刻で名前が付きます。
2. **クリップ** で素材を選ぶ。**すべて選択** で構いません。使えないものはツールが捨て、何を捨てたかを伝えます。
3. **編集を作成** を押す。進行状況バーが、素材の読み込み・ショットの認識・マッチング・書き出しを追いかけます。数分の 4K なら初回で5分程度、一度読んだ素材なら数秒です。
4. **プランを読む。** **プラン** に、一行の要約、警告、全クリップの帯が表示されます。ブロックをクリックすると、その位置に入り得た他のショットが見られ、納得がいかなければ差し替えられます。
5. **シーケンスを作成** を押す。Premiere に新しいシーケンスができます。各段階が取り消し1回分なので、⌘Z が「直前200手のうちの最後」になることはありません。

開いているものには、どの段階でも一切手を触れません。

## 何をしたいかを伝える

方法は3つあり、重ねて使えます。まず手を伸ばすべきなのは、書いた文章です。

### 言葉で

入力した一文は、編集について何を述べているかとして読まれます。

| 書くと | こうなります |
|---|---|
| 「15秒」「1分30秒」 | 尺が決まります |
| 「tiktok」「縦動画」「vertical」 | 画面比率が決まります |
| 「テンポ速め」「ゆっくり」「punchy」 | テンポが決まります |
| 「プロモ」「ポッドキャスト」「リール」「promo」 | 編集の種類が決まり、その背後のしきい値も決まります |
| 「字幕」「with subtitles」 | .srt を書き出します |
| 「店先から始めて、次にシェフ」 | そのままショットの並び順になります |

認識されたものは **設定を表示** の横の行に読み返されるので、何かを押す前に、何が伝わったかを目で確かめられます。

### この動画のように

**この動画のように** は参考動画を受け取り — 参考動画フォルダから選ぶか、リンクを貼ります — そのショット数、各ショットの長さ、そして順序を写し取ります。参考動画は計測されたうえで捨てられます。その1コマもタイムラインには入りません。

各ショットが**何を写しているか**も、手持ちの素材で賄える場合には合わせます。賄えない場合はそう伝えます。**リズムのみ** はタイミングだけを求める指定です。参考動画の音楽が音楽ライブラリにあれば、その曲に合わせて編集されます。

### 音楽に合わせて

**音楽** の **自動** は、ラッシュと一緒に置かれた音声ファイルが1つだけある場合にそれを見つけます。それ以外は音楽ライブラリから曲を選びます。カットはその曲のビートに乗ります。

流行っているのは曲の頭ではなく曲中のある瞬間であることがほとんどなので、**試聴** を押すと Premiere 自身のソースモニターでその曲が開きます。耳で見つけたところで **再生ヘッドの位置を開始点にする** を押します。尺を空欄にすると音楽が編集の長さに従うので、最後のコマを越えて鳴り続けることはありません。

### 手動で

**設定を表示** を開くと、文章が設定したはずのものがすべて出てきます。画面比率、尺、テンポ、カット間隔、フレームレート、話されている言語。さらに字幕、文を途中で切らない、無音の削除も。その上の行には、実際に設定されている内容が常に読み返されます。

その下にある編集方針そのもの — どれだけの無音を「間」とみなすか、どのフィラーを削るか、1ショットをどこまで伸ばせるか — は、コードではなく `engine/recipes/*.yaml` にデータとして置かれており、編集できます。[カッティングガイド](docs/cutting-guide.ja.md)を参照してください。

## うまくいかないとき

右下の **不具合を報告**、そして **送信用のレポートを作成**。デスクトップに zip が書き出され、両方のログ、このビルドのバージョン、直近8件のジョブが入ります。パネルが開かないときは `./report.sh` がターミナルから同じことをします — そして、それが最も必要な場面です。中身は素材の**ファイル名**、フォルダのパス、入力した文章、字幕のテキストです。映像も音声も認証情報も入りません。

この引き出しにはログも入っており、閉じている間に起きた問題の件数を表示します。

**更新を確認** は右上です。何をするかではなく、今どういう状態かを表示します — **最新です**、あるいは **更新があります**。確認だけでは何もインストールされないので、押して確かめること自体に副作用はありません。インストールの最後は **Premiere を再起動** で終わります。UXP はパネルを起動時に一度だけ読み込むため、ここだけは代わりにやってあげられません。

挙げておく価値のある失敗が3つあります。

- **「編集を作成」を押しても何も起きない。** ヘルパーが動いていません。`./setup.sh --check` を実行してください。
- **すべてのショットが弾かれた。** 素材が使い物にならないのではなく、品質のしきい値がその素材に合っていません。レシピの `visual:` ブロックにある `min_sharpness` と `min_brightness` を下げてください。
- **ドライブが外れている。** これはエラーではありません。そのフォルダがスキャンから外れ、残りはそのまま動き、パネルが何が見つからないかを名指しします。
