# カットを操る

**[English](cutting-guide.md) · 日本語**

[README](../README.ja.md) では、ほとんどの編集を決める3つのこと — 入力した文章、参考動画、そしてその背後の設定 — を扱いました。ここはその残りです。各コントロールが実際に何をするのか、無音素材をエンジンがどう扱うのか、音楽がどう選ばれるのか、そして編集方針そのものをどう変えるのか。

コマンドラインからの使い方もここにあります。パネルがやっていることはすべて、その下のエンジンがやっていることであり、エンジンは単体でも使えます。

> **この日本語ドキュメントは作者が書いたもので、母語話者によるものではありません。** 訂正は [Issue](https://github.com/OwenLangley/premiere-autoedit/issues) でも Pull Request でも歓迎します。

## コマンドラインから

### ジョブごと

エンジンをラッシュに向けます。初回は文字起こしを行い、それ以降はキャッシュが効きます。

```bash
./.venv/bin/autoedit plan --job EP001 --recipe podcast-2cam --media ~/Footage/EP001/*.mov --media-root ~/Footage --model large-v3 --out ~/AutoEdit-jobs/EP001.editplan.json
```

そのあとパネルで、プランを選び、要約と警告を確認し、**シーケンスを作成** を押します。必ず*新しい*シーケンスが作られ、⌘Z 一回で全体が取り消せます。

### マルチカメラ

ロールは、レシピで定義されたとおりにソースをトラックへ割り当てます。

```bash
./.venv/bin/autoedit plan --job EP001 --recipe podcast-2cam --media camA.mov camB.mov --role cam-a cam-b --media-root ~/Footage --out ~/AutoEdit-jobs/EP001.editplan.json
```

### 無音素材：プロモと B ロール

使える音声がない素材は、代わりに映像からカットします。ショット検出が切れ目を見つけ、品質評価が黒コマ・フリーズ・ピント不良・手ブレを捨て、音楽ベッドがカットをビートに乗せます。

```bash
./.venv/bin/autoedit plan --job PROMO01 --recipe promo-silent --media ~/Footage/broll/*.mp4 --music ~/Footage/track.wav --media-root ~/Footage --out ~/AutoEdit-jobs/PROMO01.editplan.json
```

**音楽ベッドは自動で見つかります。** 音声のみのファイルを1つだけ素材の隣に置けば、`promo-silent` がそれを使います。フラグは要りません。

```bash
./.venv/bin/autoedit plan --job PROMO01 --recipe promo-silent --visual --media ~/Footage/*.MP4 --media-root ~/Footage --out ~/AutoEdit-jobs/PROMO01.editplan.json
```

```
music: found million dollar baby.mp4 in /Users/you/Footage
music: 92.0 BPM, 92 beats, confidence 0.53
```

これが働くのは候補が**ちょうど1つ**のときだけです。複数あるときは一覧にして尋ねます。プロモを違う曲に合わせてしまうことは、質問されるより悪いからです。拡張子は信用しません。映像ストリームのない `.mp4` として書き出された曲も候補になります。`--music` で上書きでき、`--no-music` で使わないようにできます。

これはレシピごとの設定（`auto_music: true`）で、`promo-silent` だけが有効にしています。ポッドキャスト系のレシピは、編集者が自分で足すベッドのために `music` ロールを宣言しており、ラフカットに黙って音楽が付いていたら嫌な驚きになるからです。

**あるいはパネルで曲を選びます。** 自動が扱えるのはラッシュの隣にある1つのファイルだけで、本物のライブラリはそういう形をしていません。パネルの **音楽** のドロップダウンは、見えている音声のみのファイルをすべて、2つの場所から並べます。

- パネルの設定で一度指定する **音楽フォルダ**。ライブラリのある場所であればどこでもよく、素材がどこにあるかとは関係ありません。
- **素材と一緒に**置かれている音声のみのファイル。そうと分かるラベルが付くので、2つが混ざることはありません。

```
~/Music Library/            <- 音楽フォルダ
  Upbeat/drive.mp3          <- 「Upbeat/drive - 2:12」として表示
  Cues/sting.wav

/Volumes/Footage/EP001/     <- 素材フォルダ。まったく別の場所
  C1367.MP4  C1371.MP4
  scratch-track.wav         <- 「scratch-track - 0:30（素材と一緒）」
```

パネルでフォルダを選ぶと、ジョブフォルダ内の `config.json` に書き込まれます。ヘルパーは実行中にこれを読み直すので、再起動なしで反映されます。ターミナルからは `helper/install.sh <jobs> <media> [music]`、またはウォッチャーへの `--music` が同じことをします。

ライブラリの曲はリクエスト内で `library:` と印が付き、ヘルパーはどちらのルートで解決すべきかを、片方ずつ試すのではなく把握できます。ここで推測を誤るとプロモが違う曲に合わせられ、再生するまで誰も気づきません。プランは曲を絶対パスではなく `relPath` と `root: "music"` として記録するので、NAS を移しても設定変更で済みます。

音声のみかどうかは拡張子ではなくインデックスのプローブが判断します。だから `.mp4` として書き出された曲は、クリップ一覧に紛れ込まずに音楽として提示されます。スキャンは3階層・400ファイルで打ち切られ、どちらかに達した場合は黙って一覧を短くするのではなくパネルで報告されます。

**試聴と、曲のどの部分を使うかの指定。** 流行るのは曲の中のある瞬間 — ドロップ、フック、誰もが知っている8小節 — であって、曲の頭であることはほとんどありません。**試聴** を押すと Premiere 自身のソースモニターでその曲が開いて再生されます。耳でドロップを見つけたら **再生ヘッドの位置を開始点にする** を押します。

UXP は音声をまったく再生できません。`<audio>` も Web Audio もありません。つまりこれは回避策ではなく、誠実にやろうとすればこれしかない方法であり、しかも編集者にはパネル内に作り直した粗悪な何かではなく Premiere の波形とスクラブが手に入ります。試聴しても読み込みはされません。5曲から選べば4曲がビンに残ってしまいますから。

```bash
./.venv/bin/autoedit plan --job PROMO01 --recipe promo-silent --visual --media ~/Footage/*.MP4 --media-root ~/Footage --music ~/Music/drive.mp3 --music-start 30 --music-length 20 --out ~/AutoEdit-jobs/PROMO01.editplan.json
```

```
music: 92.0 BPM, 92 beats, confidence 0.53
music: start moved 0.20s to the nearest beat, at 30.20s
music: the music runs 12.1s past the last frame of picture -- extend the edit or shorten the chunk
```

**開始点は最も近いビートに吸着します。** これは飾りではありません。ショットの長さはすでにビート間隔の整数倍になっているので、ベッドがちょうどビート上で始まれば、カットのグリッド全体が耳に聞こえるものと位相を合わせます。移動量は最大でも半ビートで、聞き取れる程度に大きいときだけ報告されます。3ミリ秒の補正を「0.00秒移動しました」と告げるのは、編集者が読まねばならない一覧の中のノイズです。`--no-music-snap` で無効にできます。

**尺は、音楽が映像に優先する唯一の場所です。** 空欄にすればベッドが編集の長さに従うので、最後のコマを越えて残ることはありません。指定すれば、映像より長くなってもその長さの音楽が敷かれ、どれだけ超過するかを警告が伝えます。チャンクを選ぶとは音楽のある範囲を選ぶことであり、黙って短くしてしまえば選んだ意味がなくなるからです。

無音素材でテンポを効かせるのは、曲を選ぶことです。同じ2クリップを `punchy`、最長10秒で：

| 音楽 | ショット数 | ショットの長さ |
|---|---|---|
| なし、または見つからず | 4 | 34フレーム、均一 |
| `Music/Cues/sting.mp4` | 5 | 39〜40フレーム、92 BPM のグリッド上 |

素材に音声が**ある**場合でも映像からカットしたいときは `--visual` を足します。

エンジンは、何をどんな理由で捨てたかをショット単位で報告します。

```
C1367.MP4: 3 shots, 3 usable, 3 clips, kept 4.8s of 13.5s (removed 64%)
promo_reel.mp4: 5 shots, 3 usable  --  2 rejected: black frames, frozen frame
```

すべて弾かれた場合は、素材が使い物にならないのではなく、しきい値がその素材に合っていません。まずレシピの `visual:` ブロックの `min_sharpness` と `min_brightness` を下げてください。

**速度。** 解析はソースを3回デコードします。4K HEVC ではこれが費用のすべてで、VideoToolbox と縮小解析を使っても19秒の素材に約55秒かかります。プロキシからカットすると劇的に速くなり、計測値は同じです。

**ビート検出は曖昧さについて正直です。** 半分か倍かというテンポの問題は、範囲の端では本当に音楽的な問いなので、黙ってどちらかに決めるのではなくグリッドがその旨を示します。カットが曲の倍または半分の速さに感じられたら、`beats_per_shot` を半分または倍にしてください。

### カットを調整する

文字起こしは内容のハッシュでキャッシュされるので、レシピを変えたあとの再実行は即座に終わります。文字起こしのやり直しはありません。`engine/recipes/*.yaml` を編集し、同じコマンドを実行し、パネルで作り直します。14秒のクリップで3つのレシピを比べると：

| レシピ | 削除率 | 結果 |
|---|---|---|
| `client-promo` | 10% | テンポは編集者に委ねる |
| `podcast-2cam` | 12% | `um` と言い直しを削り、声は残す |
| `social-short` | 29% | `So,` や `you know` も削る |
| `promo-silent` | 該当なし | 音声なし。ショット、品質、ビートからカット |

文字起こしを強制的にやり直すには `--no-cache` を足します。

### 意外に思われる2つのこと

**モデルの選択が削除量を変えます。** カットは文字起こしの信頼度で制限されています（`min_confidence`、既定値 0.55）。エンジンは読み取れなかった発話の上ではカットを拒否し、そのことを警告に書きます。小さいモデルは信頼度を下げ、信頼度が下がればカットが減ります。実務では `--model large-v3` を使ってください。`small` は試行錯誤用です。

**何もマシンの外に出ません。** `whisper-local` は完全にオフラインで動きます。初回だけモデルをダウンロードし（`small` で約460MB、`large-v3` で約3GB）、以降は一度もしません。

## この動画のように切る

**新規編集 → この動画のように。** 参考動画を選ぶか、リンクを貼ると、編集はそのショット数、各ショットの長さ、そしてその順序を受け取ります。参考動画は計測されて捨てられます。その1コマもタイムラインには入りません。

0.50 / 3.00 / 0.50 / 2.00 秒で作った参考動画に対して検証したところ、編集は 0.50 / 2.99 / 0.50 / 2.00 で出てきました。6秒に対して6秒です。

写し取られるものが2つ、写し取られないものが1つあります。

- **リズム**。常に。これが確実な方の半分です。
- **各ショットが何を写しているか**。手持ちの素材で賄える場合に限ります。このリポジトリ自身のライブラリで計測したところ、同じ撮影からの参考動画は素材に対して 0.842〜0.918、無関係な3本は 0.547〜0.649 となったので、下限は 0.75 に置いています。実際に観測された幅はすべてのジョブに警告として付きます。絶対的な下限値はこの仕組みの弱い部分であり、それが間違っているなら黙っているより見えている方がよいからです。
- **参考動画の音楽は写しません。** その切り方のリズムがすでにテンポを含んでおり、そのテンポを別の曲に当てはめるのは、間違ったものを合わせにいくことになります。

参考動画のショットが手持ちの素材に1つも見つからない場合 — 被写体の違う参考動画では普通に起きることです — リズムだけが使われ、ショットは品質で埋められ、パネルがそう伝えます。**リズムのみ** は、それを最初から指定するものです。

カットのない参考動画は拒否されます。写し取るパターンが存在しないからです。原因は2つとも名指しされます。本当にワンテイクなのか、トランジションが緩やかすぎて検出できないのか。

### 参考動画フォルダとリンク

**設定 → 参考動画フォルダ** が、音楽フォルダと同じやり方で参考動画の置き場所を指定します。ファイルピッカーはありません。UXP はこのパネルに一度もそれを与えておらず、任意のパスに対する `getEntryWithUrl` は拒否され得るとドキュメントに書かれています。

貼られたリンクはヘルパーがダウンロードします。パネルではありません。パネルにはネットワーク権限が一切ないからです。ジョブフォルダの下に URL をキーにキャッシュされ、720p で取得されます。どうせ計測して捨てるファイルだからです。

**YouTube、TikTok、Instagram からのダウンロードは、一般にそれぞれの利用規約に反します。** また `yt-dlp` の抽出処理はそれらのサイトが変わるたびに壊れるので、この部分は時々更新が必要です。どちらにせよ成果物はあなた自身の素材です。リンク欄を使うかどうかはあなたの判断です。

### 参考動画の音楽

音楽が **自動** のままで参考動画が与えられると、ツールは参考動画を聴き、その曲をあなたの音楽ライブラリの中から探します。そこにあれば、編集はその曲に合わせて切られます。参考動画に合わせて切る編集者は、たいていその参考動画の音楽を使いたいと思っており、しかもそのファイルをすでに持っています。100項目のドロップダウンからそれをもう一度見つけ出すのは、機械にできる探し物です。

照合はランドマーク・フィンガープリンティングで行います。スペクトログラムのピークの組を、*同じ*時間オフセットで一致する数によって採点します。この最後の部分がナレーションに耐える理由です。ノイズも偽の一致を生みますが、それらは1つのオフセットに積み上がらず、曲全体に散らばります。ここにある実際の103曲のライブラリに対し、30秒の抜粋を AAC に再エンコードして計測しました。

| 音楽に重なっているもの | スコア |
|---|---|
| なし | 2917 |
| 音楽と同じレベルの音声 | 2787 |
| 音楽の4倍のレベルの音声 | 2566 |
| 強いピンクノイズ | 2643 |
| クリーンだが音楽が10秒だけ | 975 |

さらに、10曲を取り分けてそれぞれを**その曲を含まない**ライブラリに対して照合したところ、誤一致の最高値は **8** でした。下限は100で、どちらの端にも寄らず、その隙間に置かれています。ライブラリにない曲は一致もせず音楽も付きません。それが正しい答えです。

ライブラリのフィンガープリント作成はヘルパーがバックグラウンドで行います。100曲で約3分、一度だけ、内容のハッシュでキャッシュされます。

**これは参考動画を使うマシンでしか起きません。** 照合には照合先が必要なので、それ以外の人にとってインデックス作成は純粋な負担です。処理はパネルで参考動画が選ばれた瞬間に始まります。これは「作成」が押される数分前、まだクリップを選んでいる最中なので、最初のジョブが走るころにはライブラリはたいてい準備できています。参考動画を要求するジョブもこれを予約します。メッセージを送れなかったパネルへの保険です。

インデックス作成はジョブが組まれている間は脇に寄ります。どちらもデコード律速であり、同じコアの上で ffmpeg を2本走らせると、誰かが待っている方が遅くなるからです。

まだ聴かれていないライブラリは一致を返さず、プランがそう述べます — 「音楽ライブラリをまだ聴いています（103曲中0曲）」。途中までのライブラリは一致を見つけられないことはあっても、間違った一致を見つけることはありません。

費用は100曲で約40秒、一度だけ、ディスク上で12MB です。フィンガープリントは照合中に一度に全部ではなく1つずつ読み戻されるので、照合に必要なメモリはライブラリの大きさとともに増えません。

## 素材が複数の場所にある場合

**設定 → 素材フォルダを追加。** デスクトップに今回のラッシュ、外付けドライブに先月のもの、というのが普通の状態であり、素材フォルダが1つというのは常にその単純化でした。

各フォルダは `media`、`media2`、`media3` という独自の名前でインデックスされ、クリップはその名前とフォルダ内のパスとして記録されます。だから `C0001.MP4` を持つ2枚のカードは、別々の2つのクリップのままです。ルートが違うので区別され、クリップの選択画面がどちらのフォルダから来たかを示します。プランには絶対パスが入らないので、「ライブラリを移動して設定を1つ変えるだけ」という約束は保たれます。

**接続されていないドライブはエラーではありません。** そのフォルダはスキャンから外れ、残りのライブラリはそのまま動き、パネルは理由も言わずにクリップを減らすのではなく、何が見つからないかを名指しします。接続し直せばクリップは戻ってきます。

UXP はフォルダへのアクセスを1つずつしか許可しないので、フォルダごとに選択が必要です。最初の許可を広げてドライブ全体を覆うことはできません。

## フレームレート

**設定 → 設定を表示 → 尺とテンポ → フレームレート。** 既定は **素材に合わせる** で、従来どおりの動作をします。レシピがレートを宣言し、そこにぴったり乗れない素材がそれを押しのけ、警告がそう伝えます。

レートを選ぶと、それは納品仕様になります。素材が割り切れない場合でも尊重されます。「放送用に25」は好みではなく要件だからです。混在レートの警告は、リサンプルされるファイルを引き続き名指しします。

60を超える値は提示も受理もされません。Premiere はそれより速いプリセットからシーケンスを作成できないためです。所見 12f（英語）を参照してください。

## レシピ

編集方針はコードではなく `engine/recipes/*.yaml` にあるので、プロデューサーが調整できます。5つ同梱されています。

| レシピ | min_silence | フィラー | 意図 |
|---|---|---|---|
| `podcast-2cam` | 0.50s | conservative | 会話らしさを保つ。切りすぎたポッドキャストは不自然に聞こえる。 |
| `social-short` | 0.25s | **aggressive** | `like` や `you know` を切るのが正しい唯一の形式。 |
| `client-promo` | 0.70s | conservative | 音楽主導。意図的に控えめ。リズムは編集者の手に残す。 |
| `long-form` | 0.80s | conservative | YouTube とドキュメンタリー。人は考えるときに間を取る。 |
| `promo-silent` | 0.50s | conservative | モンタージュ。映像からビートに合わせて切るので、この2つはほとんど関係しない。 |

レシピの綴り間違いは黙って無視されるのではなく拒否されます。何もしない設定は、クラッシュより悪いからです。

**パネルにレシピの選択肢はありません。** 文章がそれを選びます。各レシピの `format` ブロックが宣言する `keywords` から決まります。「キッチンの B ロールのモンタージュ」は `promo-silent`、「2カメのポッドキャスト」は `podcast-2cam` です。認識されたときはその名前が **設定を表示** の横の行に現れるので、編集者はその語が伝わったことを目で確かめられます。これを伝える方法は一時期3つ — カード、ドロップダウン、文章 — ありましたが、2つがこの順で消えました。ドロップダウンは、成果物ではなくしきい値やトラック数の言葉で話す唯一のものでもあり、それは誰の編集の選び方でもありません。

どの種類の編集も名指ししていない文章には、`default: true` を宣言しているレシピ — 最も切らない `client-promo` — が使われます。既定値とは、誰も何も言わなかったときにちょうど適用されるものだからです。これを主張できるレシピは1つだけで、キーワードのないレシピは到達不能になりました。どちらもテストされています。かつてはどちらも、ファイル名の並び順で先に来たものに決まっていたからです。どのレシピが走ったかはプランに記録され、詳細に表示されるので、カットを、それを作った設定まで遡れます。

## 日本語

パネルは日本語で動き、日本語の素材も正しく切れます。言語は **設定 → パネルの言語** で選びます。マシンごとに記憶されるので、混成チームでも1つのインストールを共有できます。

**話されている言語は設定ではなく検出されます。** レシピは `language: auto` で出荷され、Whisper が音声から言語を特定し、パネルが見つけたものを表示したうえで、訂正用のドロップダウンを添えます。推測を誤ると、流暢で自信に満ちた無意味な文字起こしができあがるので、信頼度が低い場合は黙って実行するのではなく報告されます。

**フィラーの除去は機能します。そこに至るには計測が必要でした。** Whisper は日本語を単語に分割しません。

| 発話 | 返されるトークン |
|---|---|
| `えーと` | `えー` + `と、` |
| `うーん` | `う` + `ーん、` |
| `あの、` | `あの、` |

最も一般的な言い淀みの音は、決して単一のトークンにはなりません。だから1つずつ照合する方法では見つけられません。フィラーは連続するトークンの*並び*に対して照合され、空白を使わずに書く言語では何も挟まずに、それ以外では空白を挟んで連結されます。1つの仕組みが英語の "you know" も同時に覆います。

conservative は言い淀みの音だけを削除します。aggressive はあの、その、まあ、なんか も削除します。これらはフィラーとして使われる実在の語であり、英語の "like" を conservative に入れないのと同じ判断です。`うん` と `ええ` はどちらにも意図的に入れていません。これらは*はい*を意味しており、インタビューから相手の同意を切り取るのは、種類の違う間違いだからです。

警告も翻訳されます。エンジンは文ではなく、キーと数値を出力します。

```jsonc
{ "code": "music", "messageKey": "music.stopsEarly", "params": { "shortfall": 0.1 },
  "message": "the music stops 0.1s before the picture does" }
```

だからパネルは「音楽が映像より 0.1 秒早く終わります」と表示でき、まだ翻訳のない警告は消えるのではなく英語のまま出ます。警告を読めない編集者は、警告を見ない編集者より悪い状況にあります。問題がないと思い込んでしまうからです。

**意図的に翻訳していないもの：** クリップごとの `reason` 文字列（「shot 3 of 14, quality 0.71」）。これらはパネルではなくプランの JSON にあり、翻訳するとカタログが3倍になる一方で、編集者にとっての利得はありません。

**この日本語は、母語話者ではなく、このツールの作者が書いたものです。** 尺やテロップのような語は、翻訳が流暢なまま間違っているという結果になりやすいところで、明らかに壊れているより見つけにくいものです。世に出す前に `panel/src/i18n.js` を誰かに読んでもらう価値があります。
